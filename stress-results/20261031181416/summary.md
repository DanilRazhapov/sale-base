## Обнаруженная проблема с восстановлением входа

Перед продажами кассовый API вернул HTTP 409: у «Аллигатора» оставалась действующая серверная сессия, хотя открытой кассы у пользователя не было. Она истекала 1 ноября в 09:27 по Бишкеку. Закрытие вкладки не завершает сессию, а повторный вход блокируется до выхода или истечения срока.
Для продолжения завершена только конкретная старая сессия через привязанный Supabase CLI. Открытая смена сохранена. Изменений логики авторизации или схемы БД не выполнялось. После этого 300 продаж и 10 повторов прошли без ошибок. HTTP 409 относится к подготовке теста и не входит в ошибки продаж.

## Область проверки и оставленные данные

Тест выполнен через штатные запросы приложения: Supabase Auth владельца, REST создания категорий, RPC save_store_product и Edge Function cashier-terminal с входом по имени/PIN. Продажи выполнялись с отдельной PIN-сессией, без JWT владельца. Запись продаж напрямую в таблицы не использовалась.
Это ограниченная проверка API и согласованности данных: один кассир, один магазин, до пяти одновременных запросов. Задержки включают сеть и Edge Function. Работа интерфейса, пределы производительности, длительная нагрузка, множество магазинов и кассиров, CPU и память сервера не измерялись.
Тестовые категории, товары и продажи сохранены в магазине. Действующая до теста смена оставлена открытой; тестовая кассовая сессия завершена. Выручка теста входит в учёт магазина.
Пароли, PIN и токены в отчётах не сохранялись.
